# 借鉴：dsh-linghun 的认知主体设计

参考仓库：<https://github.com/syyr1987/dsh-linghun>（AGPL-3.0，"山越野人 × 岚客"）。
参考的是**设计思路**，代码是照会议场景重写的，没有整份复制。

## 它解决了什么问题

linghun 的定位不是记忆插件，是**认知主体**：

> 大模型提供直觉素材，agent 做评估、筛选、收口——
> 思考、判断、决策在 agent 侧完成。

对比我们原来的做法：只把"人格"当资料拼进 prompt，模型看完照样自由发挥。
它是把"谁来做判断"这件事显式化了。

## 我们采纳了四处

### 1. 两层身份：用户卡 + 认知架构

| 层 | 谁写 | 内容 |
|---|---|---|
| **USER-CARD** | 用户，只填四个空 | 名字 / 性格 / 沟通风格 / 其他 |
| **认知架构** | 插件垫底，用户不用写 | 承接即预检、失守信号 |

**为什么分开**：

1. 用户不该为了"让它像自己"去学提示词工程
2. 架构是**纪律**，不是人格；混进用户卡会被一次随手编辑删掉
3. 合并时"用户在上、架构在下"，不冲突、不覆盖

解析优先级照抄它的思路：**文件 > 配置 > 默认卡**。
首次运行自动落一份模板（`<人格目录>/USER-CARD.md`），改完即生效。

代码：[lib/soul-card.js](../lib/soul-card.js)

### 2. 三分法本体

会议里捞到的东西分三类存，因为**寿命与用途完全不同**：

| 类 | 落到哪 | 寿命 | 例子 |
|---|---|---|---|
| 技术知识 | `knowledge.md` | 长期，越多越好 | "WebSocket 要按帧解析，不能按行读" |
| 项目记忆 | `memory/YYYY-MM-DD.md` | 会过期 | "本周灰度上线" |
| 经验规则 | `rules.md` | 少而稳 | "以后遇到延期，先给替代方案再报风险" |

**混在一起的后果**（这是 linghun 的核心洞见）：
三个月前的项目进展被当成"当前状态"，随口一句被当成"规则"，模型只能一起信。

分类顺序也有讲究：先看是不是**经验纪律**（最容易被误判成普通事实），
再看是不是通用知识，剩下归项目记忆。

代码：[lib/tripartite.js](../lib/tripartite.js)

### 3. 稳定特质折叠

对应 linghun 的 `soul_update`：**只有反复被强化的条目**才有资格写回用户卡。

- 追加在 `## 自动沉淀（反复出现，已稳定）` 小节
- 不覆盖手写内容
- 去重，有上限（默认 12 条）

代码：`foldStableTraits()`（[lib/soul-card.js](../lib/soul-card.js)）

### 4. 规则按需注入，而不是全量灌

linghun 用「本体主题索引优先 + BM25 兜底」控制注入量。
我们的会议场景更简单：**主题二字片段命中**即可（`hitRules`），
注入时只取最近 5 个主题 × 每主题 3 条。

> 不这么做的话，规则越长越像噪音，token 也跟着涨。

## 我们**没有**采纳的

| 它的设计 | 为什么没抄 |
|---|---|
| 暖态/冷储/episodic/journal 四层记忆 | 会议场景的"记忆"主要是会议账本 + 项目进展，已有 `transcript.jsonl` 与三分类承载，再加四层是重复 |
| BM25 检索 + rubric 维度强制检索 | 那是为了让 agent 回答评测题；我们只在会上注入规则，用不上 |
| 判据指纹断言（防判据被悄悄改宽） | 值得借鉴，但需要"判据"这一层抽象；当前先做成待办 |
| 双实例互验（打破自指悖论） | 会议场景不需要，成本高 |
| 完整的"承接即预检→悖论处置协议" | 太长。会议里只需要"复述→类型→自查"三步 |

## 差异：它是认知主体，我们是"以她身份在场"

```
linghun  ：你是谁？你如何判断？如何自我改进？
soulmirror：她是谁？她会怎么说？我能不能替她说这一句？
```

所以同样的"身份锚点"，重点不同：

- 它强调**有主见**（可以反对用户）
- 我们强调**是影子**（不许替她承诺）

这条写进了认知架构的失守信号里：

```
- 用她的名义承诺了时间、金额、人力 → 停
- 把别人的观点说成她的立场 → 停
- 为了显得像她而模仿口头禅，却丢了判断 → 停
```

## 待办（借鉴了但还没做）

1. **判据指纹**：给"红线/分寸"这类判断规则算 hash，防止被后续生成悄悄改宽
2. **规则退化**：长期没被命中的规则自动降权或归档
3. **负面样本**：用户卡里加"我不会说的话"，对风格约束比正面形容词更有效
