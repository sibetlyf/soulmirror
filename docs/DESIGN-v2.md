# SoulMirror 2.0 设计方案

> 状态：设计稿（未实现）
> 目标：把现在的"能用但脆"的会议插件，重做成符合 DSH 插件规范、可直接交付的水准。

---

## 0. 先说结论：现在的问题到底在哪

| 现状 | 问题 | 影响 |
|---|---|---|
| `index.js` 约 2700 行，40 个工具、采集、ASR、TTS、人格、记忆、知识库全在一个文件 | 没有边界，改一处炸一片 | 每次改动都要全量回归，实测一周内出了 3 次白屏/卡片失效 |
| UI 是自绘常驻浮层 + 自造样式 | 和 DSH 原生界面不一套体系 | 用户在侧栏/会话里找不到入口，切换形态时逻辑各写一份 |
| 采集设备"自动挑最响的" | 踩中 HDMI 环回静音 | 采到的全是静音，表现为"没有实时转写" |
| 60 秒无转写就换设备重采 | 换设备=杀进程重启=丢音频 | 无限抖动，表现为"转写是几分钟前的" |
| 单句一条 LLM 纠错（串行） | 队列积压时行号延迟 | 转写时间戳是新的、内容是旧的 |
| 说话人靠"读客户端悬浮窗" | 只有腾讯会议有，移动会议没有 | 一半场景识别不出说话人 |

2.0 的核心不是加功能，是**把"事件流 + 状态机 + 原生 UI"三件事做对**。

---

## 1. 目标与非目标

### 目标（对应你列的 6 条）

1. 实时转写 + 说话人识别
2. 自动检测会议软件、捕获会议号
3. 通过对话创建并加入会议
4. 可开关的 Agent 自动化（判断"有人在对我说话"→ 执行任务 → 回复）
5. 会后自动归档
6. 与 DSH 原生 Web 一致的 UI/UX

### 非目标（明确不做，避免摊子铺太大）

- 不做跨平台（Windows 优先；macOS 作为后续阶段，架构预留）
- 不自研 ASR/TTS 模型（用 DashScope / 系统 SAPI，接口可换）
- 不做会议录制视频（只处理音频 + 转写文本）
- 不做多人声纹长期库的云端同步（本地为主）

**关键原则**

- Host 只做"状态 + 音频 + 模型调用"，不碰 UI
- Client 只读 `GET /api/soulmirror/live`（SSE 推状态，HTTP 兜底）
- 事件流单向：音频 → 转写 → 判定 → 动作 → 归档，每级可单独关掉

## 3. 子系统设计

### 3.1 音频采集（audio-engine）

**设备选择：启动时定一次，锁定，永不自动切换**（已实现，保留）

```
1. 配置 devices.capture 显式指定
2. 否则 = 系统默认播放设备（mbridge default 报的那个）
3. 探测例外：若此刻别的设备在响且默认设备电平≈0 → 用它 + 记日志
```

**用 `pickCaptureDevice()` 纯函数**决定，可单测。

**永不自动换设备**。长时间无声只报警：

> 采不到声音：当前设备「X」的环回是静音，有声音的是「Y」，请把系统播放设备切到它

**故障处理（进程级）**

| 故障 | 检测 | 动作 |
|---|---|---|
| 采集进程退出 | child exit | 指数退避重启（1s/2s/4s，最多 5 次），超限则停并上报 |
| 采集无字节 | 5s 内 bytes=0 | 重启一次；再失败标记 error，不再抖 |
| 采集全静音 | 逐包 RMS | 只记录 `silentFrames`，**不换设备** |

**真·设备无关方案（M2 评估）**：WASAPI **进程环回**（`VAD\Process_Loopback`）能直接采某进程声音，不受输出设备影响。
现状：`ActivateAudioInterfaceAsync` 在 .NET Framework 下报 `E_ILLEGAL_METHOD_CALL`（已实测）。
对策：桥接程序改用 **.NET 8 单文件** 或 **C++/WinRT** 重写；这是彻底解决 HDMI 静音问题的唯一正路。

### 3.2 转写与说话人（asr-stream + diarization）

#### 转写流水线

```
capture-stream (16k mono PCM16)
   → DashScope paraformer-realtime-v2（WS 长连接）
   → partial（每 ~200ms 刷新）──▶ 实时字幕（不落库）
   → sentenceEnd 或 超 4s 未变且 ≥8 字 ──▶ 正式行（落库 + 事件）
```

**延迟指标**（验收用）

| 指标 | 目标 |
|---|---|
| partial 刷新间隔 | ≤ 500ms |
| 落地延迟（说话 → 出现正式行）P50 | ≤ 2s |
| 同上 P95 | ≤ 5s |

#### 说话人识别：三层策略（诚实版）

第三方实时 ASR **不提供说话人分离**（paraformer-realtime-v2 已实测无该参数）。所以分三层：

**L1 客户端发言人（最准，仅部分客户端）**
- 腾讯会议：`FloatSpeakingWnd` 暴露当前发言人
- 移动会议：`VideoCellWnd` 里没有说话人名字文本 → 不可用
- 命中则直接打标，置信度 1.0

**L2 声纹聚类（通用，需模型）**
- VAD 切句 → 每句取 1.5–6s 有效段 → 算 speaker embedding（3D-Speaker CAM++ ONNX，~30MB，CPU 可跑）
- 在线聚类（余弦相似度 + 阈值 0.72，增量质心）
- 输出 `speakerId = spk_1 / spk_2 …`
- 会议中可"点一下改名"→ 映射到真实姓名，后续同质心自动用真名
- 目标：2–6 人会议，纯度 > 85%（这是可用线，不是论文线）

**L3 兜底**
- 都没命中 → `speaker: '—'`，不猜
- UI 明确显示"说话人未识别"，不假装识别到了

**音频留存**：默认只存文本 + 声纹向量（不存原始音频）；`capture.saveAudio=on` 时才存 wav，用于事后重跑/调试。

### 3.3 会议检测与会议号（detector）

**检测（5s 轮询，仅在总开关打开时）**

```
进程白名单 → 窗口类名/标题 → 评分
腾讯会议 100 / 移动会议 90 / 飞书 80 / 钉钉 70 / Zoom 60 / Teams 55
取最高分；低于 60 视为"没开会"
```

**"在会中"判定（三个信号，任一命中）**

```
1. 窗口类名属于会中类（FloatSpeakingWnd / VideoMainWindow / MeetingView …）
2. 标题 != 软件名（腾讯会议会变标题）
3. 该进程正占用麦克风（mbridge mic-usage state=1）   ← 移动会议靠这条
```

**会议号提取（按可信度降序，命中即停）**

| 优先级 | 来源 | 例子 |
|---|---|---|
| 1 | 会议内文本控件（如腾讯会议悬浮窗 `Text`） | `983 593 253` |
| 2 | 带标签的剪贴板/窗口文本 | `移动会议：379422987`、`会议号 206-275-219` |
| 3 | 邀请链接 | `…/share/379422987`、`…/dm/xxx` |
| 4 | 裸号（三位分组 / 9–11 位，排除 19xx/20xx 日期） | `983593253` |
| 5 | 官方 API 反查（腾讯会议插件可用时） | 按进行中会议列表匹配 |

**规则**：一个都命中不了就显示"未识别（该客户端不暴露会议号）"，**绝不编造**。用户可以手填一次，本次会话记住。

### 3.4 会议生命周期（meeting-core 状态机）

```
        ┌──── idle ────┐
        │              │ 检测到会中（连续 2 tick）
        ▼              │
   arming ──▶ capturing ⇄ paused
        │              │
        │ 检测到会议结束 / 手停
        ▼              ▼
   finalizing ──▶ archived ──▶ idle
```

**每个状态的可观测字段**：`state / since / app / code / device / lines / lastError / health`

**关键不变量**

- `capturing` 时必定只有一个采集进程（用进程表断言，防重复）
- 任意状态切换都写 `events.jsonl`（可回放）
- 任何 `error` 都必须带一句"用户能做什么"

### 3.5 入会与创建会议（meeting-ops）

**优先级：链接 > 官方 API > 界面点击**

```
1. 手里有入会链接（https://…/dm/xxx、…/share/xxx）→ 直接打开，零界面操作
2. 装了腾讯会议官方插件且有凭据 → 用 API 创建/查询，拿链接后走 1
3. 只有会议号 → UIA 填号点加入（需标定）
4. 标定失效 → 触发一次 computer-use 自愈标定（每月最多 1 次，防刷）
```

**标定（calibration）**

- 首次安装：自动跑一次探索，把按钮位置按**相对比例**存进 `~/.dsh/soulmirror/uimap.json`
- 失败计数 ≥3 或客户端版本变化 → 标记 `needsRecalibration`，触发自愈
- 全程不写死像素坐标

**对话创建会议**（新能力）

```
用户："帮我约下午三点的周会，30 分钟"
→ meeting_create {title, start, duration, invitees}
  ├─ 有腾讯会议凭据 → 走官方 API（拿到链接 + 会议号）
  └─ 没有 → 走界面「预约会议」+ 标定
→ 结果作为 artifact 返回（链接可点）
→ 到点自动参会：写进 DSH「自动化任务」（复用 schedule 服务，不自造定时器）
```

### 3.6 Agent 自动化（agent-brain）

**开关：单一总开关 + 模式**

```
enabled=false → 什么都不做（含不采集）
enabled=true  → mode=transcribe | agent
```

**判定"是否有人在对我说话"（这是第 4 条的核心）**

四路信号打分，加权求和，阈值可配：

| 信号 | 说明 | 权重 |
|---|---|---|
| 称呼 | 文本含我的名字/昵称/职位（可配列表） | 0.35 |
| 疑问句式 | 「能不能/是不是/怎么办/帮我/你看下」 | 0.25 |
| 第二人称 | 你/您/你们 | 0.15 |
| 上下文 | 上一轮我在说话，或话题在问我（LLM 判定） | 0.25 |

- 总分 ≥ 0.6 且 `mode=agent` → 触发
- 冷却：同一话题 60s 内只触发一次，避免复读
- 预算：每分钟最多 1 次 LLM 判定；每小时发言 ≤ N 次（可配）

**执行链路**

```
触发 → 组 prompt（最近 20 句 + persona + 记忆摘要）
     → 需要查资料/算东西？→ 建/复用 DSH 会话跑（runInMeetingSession）
     → 拿到答案 → TTS（cosyvoice / SAPI）→ 播到虚拟声卡 → 会议麦克风
     → 同时在转写流里插一条 role=assistant 的记录（UI 可见"我说了什么"）
```

**发言安全**

- 发言前先 `mic` 检测：若用户正占着麦克风（在说话）→ 延后 2s 重试，最多 3 次
- 发言时长 > 30s 自动截断
- 静音/耳机场景（`devices.speak` 未配置）→ 只说给用户听（本地 TTS），不进会议

### 3.7 会后归档（archive）

会议结束（检测到退出 / 用户手动结束）后，串行执行，**每步独立可失败**：

```
1. 生成纪要：LLM 归纳（有 key）→ 否则抽取式摘要
   产出：决议 / 待办 / 风险 / 未决
2. 写文档：Markdown（标题：日期 会议名 会议号）
   - 存 ~/.dsh/soulmirror/meetings/<id>/minutes.md
   - 回写知识库（知识库可用时，按"会议 · <软件>"分组）
3. 待办落地：把 action items 注册为 DSH 自动化任务/待办（用户确认后才建）
4. 制品：原始转写 jsonl、纪要 md、声纹画像 json 一起归档
5. 汇报：给当前会话发一条消息（可关），带纪要链接
```

**保留策略**：默认保留 90 天文本、7 天音频（可配）；`archive.keepDays`。

### 3.8 UI/UX（对齐 DSH 原生）

**用真实存在的 Slot，不自绘整套界面**

| Slot | 用途 |
|---|---|
| `sidebar.panellist` | 左侧栏一个「会议」图标，点开主面板 |
| `main#meeting`（keyed） | 会议主面板：状态、会议号、实时转写、纪要、配置入口 |
| `conversation.input.dock` | 会话里的**实时字幕条**（一行，正在说话的人 + 文字 + 状态点） |
| `conversation.view#meeting` | 会话内切到「会议」视图（完整转写，可滚动、可搜索） |
| `settings.section#meeting` | 原生设置页：开关、模式、设备、ASR/TTS、归档策略 |
| `tool.call.toolview#meeting_*` | `meeting_status` 等工具调用渲染成卡片，而不是一串 JSON |

**视觉规范**

- 只用主题 token：`--dsw-alias-bg-base/layer-1/layer-2/overlay`、`--dsw-alias-border-l1/l2`、`--dsw-alias-brand-primary`、`--dsw-alias-label-primary/secondary`、`--dsw-alias-state-success/warn/error/idle-primary`
- 深浅色自动跟随（token 自带两套值），不写死颜色
- 字号阶梯：标题 20 / 卡片标题 14 / 正文 13 / 辅助 11（对齐 DSH）
- 圆角 6/8，间距 4 的倍数

**交互规范**

- 键盘可达：Tab 顺序、Enter/Space 激活、Esc 关闭
- 空态：每个区域都有"为什么空 + 怎么让它有内容"
- 错误态：一句话原因 + 一个可点动作（例如"把播放设备切到 X"）
- 加载态：骨架屏，不用转圈占位
- 不做自动滚动打断：仅当已在底部才跟随（已实现）
- 大列表虚拟滚动（>200 行时只渲染可见区）

**三段式信息架构**（避免现在"一个面板塞所有"）

```
小窗（380px，conversation.input.dock 或 shell.overlay）
  └─ 状态点 + 一句话状态 + 最近 1 行字幕 + 「展开」
主面板（main#meeting）
  ├─ 顶部：会议身份（软件/标题/会议号/时长/健康）
  ├─ 中部：实时转写（虚拟滚动 + 说话人色块 + 搜索）
  └─ 底部：纪要预览 + 归档状态
设置页（settings.section#meeting）
  └─ 开关/模式/设备/模型/归档/隐私
```

### 3.9 可观测性（商用必需品）

| 能力 | 做法 |
|---|---|
| 健康检查 | `GET /api/soulmirror/health` → `{ok, capture, asr, device, latencyMs}` |
| 指标 | 落地延迟 P50/P95、每分钟句数、采集重启次数、LLM 调用次数与耗时 |
| 结构化日志 | `events.jsonl`，按会议 id 分文件，7 天轮转 |
| 错误可行动 | 每个 error 带 `hint`（人话）和 `action`（可执行） |
| 崩溃恢复 | 采集监督者 + 状态快照；重启后能续采 |
| 回放 | 用 `events.jsonl` 能重建任意会议的完整时间线 |

---

### 3.10 隐私与合规（要卖就得有）

- **采集提示**：开启后主面板常驻"正在转写"红色指示；可选 TTS/系统通知告知参会者
- **默认不存音频**：只存文本 + 声纹向量
- **敏感信息**：转写中的手机号/身份证/身份证类自动打码（可关）
- **数据位置**：全部本地 `~/.dsh/soulmirror`，不外传（除 ASR/LLM 请求本身）
- **一键清除**：`meeting_purge` 删除某场会议全部数据
- **凭据**：复用 DSH 本地凭据服务，不落明文配置文件

## 4. 数据模型

```
~/.dsh/soulmirror/
├── config.json                  # 用户配置（不含密钥）
├── db.sqlite                    # 会议、转写、说话人、任务（新增，替代散落 jsonl）
├── uimap.json                   # 标定坐标（相对比例）
├── voices/                      # 声纹质心（每人一个 json：id, name, centroid, samples）
└── meetings/
    └── 2026-11-03_1430_983593253/
        ├── meta.json            # app/code/title/start/end/device/health
        ├── transcript.jsonl     # {t, end, speaker, text, conf, src}
        ├── events.jsonl         # 状态迁移/错误/动作
        ├── minutes.md
        └── audio.wav            # 可选
```

**为什么上 SQLite**：现在 132 行转写靠内存数组 + jsonl，做不了搜索/统计/多会议对比；商用需要"上次那场会谁说了什么"这种查询。

## 5. 代码结构（从 2700 行单体拆开）

```
soulmirror/
├── index.js                 # 仅做装配：读配置、挂服务、注册工具（<200 行）
├── host/
│   ├── audio/engine.js      # 采集监督者、设备锁定、字节计数、健康
```

## 7. 风险登记（含已知死路）

| 风险 | 现状 | 对策 |
|---|---|---|
| HDMI 设备环回恒静音 | 已实测（HDMI RMS 0.0000，MIPI 0.0454） | 锁定可采设备；进程环回作为 M2 的根治手段 |
| 进程环回 `.NET Framework` 报 `E_ILLEGAL_METHOD_CALL` | 已实测 | 桥接程序升级 .NET 8 / C++/WinRT |
| 实时 ASR 无说话人分离 | 已实测 | 三层策略（L1 客户端 / L2 声纹 / L3 显示未识别） |
| 移动会议不暴露会议号 | 已实测（UIA 无数字） | 剪贴板/邀请链接兜底；实在没有就显示未识别 |
| 移动会议会中标题不变 | 已实测 | 用麦克风占用作为"在会中"信号 |
| 客户端 UI 改版导致标定失效 | 会持续发生 | 失败计数 + 自愈标定 + 相对坐标 |
| LLM 判定延迟拖垮转写 | 已踩过 | 转写链路与判定彻底解耦（队列分离，判定不阻塞落库） |
| token 成本 | 判定/纠错都花钱 | 默认只转录；判定有冷却和预算 |
