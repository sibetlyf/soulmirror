# 声纹 / 说话人 UI 设计评审（UX Review）

- 评审对象（工作区当前未提交改动）：`lib/client.js` 的 `ArtifactsCard` / `VoiceprintCard` / `SpeakersCard`，`lib/view-model.js` 的 `view`，`index.js` 的 `/voiceprint`、`/voiceprint-enroll`、`/voiceprint-delete`、`/speakers` 与 `identify` 步骤。
- 评审立场：只做设计评审，不含代码补丁；下面每条都指到具体组件/字段/文案，可直接交给实现者。
- 证据来源：静态阅读工作区代码（`git status` 显示 `index.js`、`lib/client.js`、`lib/voiceprint/*` 有未提交改动）。**我没有实机跑过 UI**（Host 改动需重启 DSH 才生效），所以第 5 节验收清单就是留给实机核对的。
- 判定基准：用户既有的五条硬要求——状态必须可感知、所有显示共用一套配置、先落盘后展示、不静默回退、无假进度、报错说清原因和怎么办；外加"商业级 UI，不要黑块、不要点了没反应、不要找不到入口"。

---

## 1. 一句话结论

**最该先改的三件事（按收益排序）：**

1. **安装过程现在完全看不见**：`startInstall`（client.js:957-969）用一次 `fetch` 同步等完整个安装（后端 `await runVoiceprintInstall`，index.js:1760），而"是否在装"取自响应里的 `data.install.running`（client.js:946）。结果：135 MB 下载 + 解压的几分钟里，进度条、百分比、取消按钮一个都不会出现，用户只看到一个 disable 掉的「一键安装（…）」按钮。这正好是用户最反感的"点了没反应"，而它发生在最容易劝退人的第一步。
2. **没装模型也能录，而且入口难找**：`录一段注册`（client.js:1011）在未装模型时**不禁用**，用户对着麦克风说满 12 秒、点结束，才收到"没注册成功：model-missing"；同时「纪要与产物」不是默认 tab（默认 `transcript`，client.js:1126），声纹卡又排在"产物位置"路径列表之后，十秒内基本找不到"录声纹/装模型"。
3. **"谁是谁"这件事讲不清**：本机声纹库（跨会、有向量）和这场会名册（一次性、无向量）共用同一份人名提示和同一个 `datalist id`，用户会以为"名册里填了名字 = 已经注册了声纹"；而会后 `identify` 的认人结果只落成一行字符串，看不清"认出了谁、谁没认出、为什么"。

---

## 2. 逐条问题表

严重度：P0 = 违背硬要求/功能实际不可用；P1 = 会造成误解或白干；P2 = 信息不足、体验粗糙；P3 = 一致性/文案细节。

### 2.1 问题一：入口可发现性

**结论：不行，第一次用的人在 10 秒内找不到。** 依据是四道门槛叠加：

- 默认 tab 是「实时转写」（client.js:1126），目标在第 2 个 tab；
- tab 名「纪要与产物」（client.js:1187）指向"结果"，不指向"设置声纹/装模型"；
- 进 tab 后第一块是「产物位置」的路径列表（三行绝对路径），声纹卡在其下；
- 「设置」tab 里没有任何声纹入口（`SwitchesCard` 只有建议卡片/Agent 发言，client.js:1590-1597），而 `embed.js:45` 的 hint 却在教用户"在设置里指定路径"——那个入口不存在。

| # | 问题 | 影响（用户会怎么误解） | 具体改法 |
|---|---|---|---|
| P0-1 | 声纹就绪状态不出现在任何"状态"位置：`view` 里没有声纹字段（view-model.js:66-80），只有进到「纪要与产物」才触发 `/voiceprint` 请求 | 用户永远不知道自己缺了这一步；会后发现纪要里是"说话人1/2/3"，不知道为什么 | **方案 A（推荐，代价最小）**：`view` 增加一行 `voiceprint: { enabled, ready, reason, modelBytes, runtimeBytes }`（由 `/status` 直接带上，符合"状态只有一份"），状态卡在 notice 行（client.js:1210）下面加一条 inline 提示：`声纹未就绪：会后不会自动认人` + 一个「去安装」按钮，点击 `setTab('minutes')` 并滚动到声纹卡（给卡片加 `id`）。代价：`/status` 多一次 `runtimeStatus`/`modelStatus` 探测（已有缓存，可接受），不影响其它状态。 |
| P0-2 | `identify` 被跳过时提示只出现在「会后整理」步骤行里（`PipelineSteps`，client.js:1091-1101），而该列表位于同 tab 的最下方 | 用户看到"已跳过"也不知道去哪补 | 在该步骤行 detail 后加一个动作（步骤对象增加可选 `action: { label, tab, focus }`）：`去装模型` / `去开启声纹`。代价：`view-model.js` steps 多一个可选字段 + `PipelineSteps` 渲染一个按钮，改动很小。 |
| P1-3 | 「产物位置」排在声纹卡之前：进入 tab 先看到 3 行绝对路径 | 首次进入以为这个 tab 只是"文件在哪" | 把顺序改成：**与会的人（声纹 + 名册）→ 会后整理 → 产物位置**。产物是结果，放最后更符合"看结果之前先看这是谁说的"。代价：纯顺序调整。 |
| P1-4 | 没有分组标题，三张卡平铺 | 分不清哪些是"设置一次、长期生效"，哪些是"这场会一次性" | 在声纹 + 名册之上加一个小节标题（用 `S.section`，client.js:83）：`与会的人`。代价：一行。 |
| P2-5 | tab 名「纪要与产物」不含"人" | 用户不会想到里面能管理身份 | 改为 `纪要 · 产物`（保留长度）或不改 tab，只靠 P0-1 的 inline 提示引流。此条建议**只做一条**，别和 P0-1 同时上，否则入口重复。 |
| P2-6 | 「安装」这件事在「设置 → 安装与依赖」（`SetupCard`/`DepsCard`，client.js:2298/2242）里已有"一键安装"语义，但那是**可选 DSH 插件**（npm），与此处模型/运行库**完全无关** | 用户会去设置里找，看到"可选插件：全部就绪"后以为声纹也已经好了 | 不迁移安装入口（两处会打架），但要在声纹卡标题旁写明归属：`本机声纹 · 装在本插件数据目录`；并在 `DepsCard` 未装项文案里避免"一键安装"与声纹卡按钮同词（见文案清单）。代价：只改文案。 |

> 为什么不推荐把安装搬到设置页：装完模型后的下一步是"立刻录一段"，搬到设置会造成"装完还得回另一个 tab 再录"，反而多一跳；而 `DepsCard` 那套是 npm 插件安装（走 `dsh plugin add`），语义和失败处理都不一样，混在一起会复制一套状态源，违背"所有显示底层共用一套配置"。

### 2.2 问题二：安装流程的信息密度

**结论：体量说了，但"为什么/能不能不装/装完有什么变化"没串成一条；分步文案与 phase 只对上大半，失败态缺可执行动作，且进度本身到不了用户眼前（见 P0-7）。**

现状核对（phase 一一对照）：

| phase 集合（index.js:6004-6049） | 界面现在给的（client.js:947-951 + 996-1005） | 问题 |
|---|---|---|
| `resolving` | `准备中` + `开始安装：<模型名>` | 可接受，但缺"接下来要下多少" |
| `download-model` | `下载模型` + `正在下载模型 37%` + 右侧 `37%` | 百分比**重复显示两次**；且看不到已下载/总字节 |
| `verify-model` | `校验模型` + `正在校验文件完整性`，进度条停在下载结束时的数值（≈100%） | 校验期间条几乎满格却没有新事件，看起来像卡住/假进度 |
| `install-model` | `模型落盘` | 800ms 轮询基本抓不到，无感（可接受） |
| `download-runtime` | `下载运行库` + 重新从 0% 开始 | **进度条从 100% 掉回 0%**，读起来像"重来/失败" |
| `verify-runtime` | `校验运行库` | 同上，无字节反馈 |
| `extract-runtime` | `解压运行库` | 这是最慢的本地阶段（`tar -xzf`，installer.js:253-261），期间没有任何新事件；且**此阶段取消无效**（`execFile` 没传 signal），界面却立刻显示"已取消" |
| `done` | `完成` + message | 但这段只在 `installing or phase==='failed'` 时渲染（client.js:996），**成功态永远不显示**，用户不知道到底成没成 |
| `failed` | `安装失败：<error>` + hint | hint 是后端写死的三句之一（index.js:6020/6037/6047），没有"重试"按钮，用户不知道再点同一个按钮就是重试 |

### 2.3 问题三：两套人名的关系

**结论：会被当成同一件事，必须改名 + 标注来源 + 说明优先级。**

证据：两份数据在语义上确实不同（`lib/speaker-map.js:9-17` 注释：每场 `speaker-map.json` = 这场会 说话人N→姓名；全局 `speakers/people.json` = 仅输入提示、**不含声纹、不能跨会认人**），但界面上：

- 两个输入框共用同一个 `datalist id="sm-people"`（client.js:1021 与 1087）——同一 tab 内渲染两个同名 `datalist`，浏览器只认第一个，提示词取决于渲染顺序；
- 名册保存会把名字写进 `people.json`（index.js:1889），于是**下次录声纹的输入框会建议这些名字**，看起来像"这些人已经注册过"；
- 声纹卡标题「本机声纹（默认不出本机）」、名册标题「谁在说话」，都没有"跨会 / 只这场"的时间范围；
- 认人优先级（人工 > 自动）由 `index.js:5696`（`if (r.name && !map.byLabel[r.label])`）实现，界面上完全没写。

| # | 问题 | 影响 | 具体改法 |
|---|---|---|---|
| P0-18 | 用户在名册填了名字，就以为"以后会自动认出这个人" | 下一场会依旧是"说话人1"→ 判定"声纹功能是坏的" | 名册标题改 `这场会谁是谁`，副标题一行：`只对这场会有效，不会建立声纹`；声纹标题改 `我认识的人 · 本机声纹`，副标题：`录一次，以后每场会都能认出`。 |
| P1-19 | 名册输入框的建议来自声纹库同名清单，无任何标记 | 以为建议=已注册 | `/speakers` 每行增加 `hasPrint`（用 `library.people()` 与该行 name 比对）；名册行内显示 tag：`已有声纹`（`S.tag` + `T.ok`）或 `无本机声纹`（`T.muted`）。 |
| P1-20 | 自动认出的名字与人工填的名字在名册里长得一样 | 分不清"这是机器猜的"还是"我填的"，不敢纠错 | `/speakers` 每行增加 `source: 'auto' 或 'manual'`（来源：`speakers.json` 的 `results[].name` 与 `speaker-map` 的人工写入痕迹；需要 `speaker-map` 升级为带来源字段，或在保存时区分）。名册行显示：`自动认出`（`T.brand`）/ `我填的`（`T.muted`）。 |
| P1-20b | 优先级没说 | 用户以为改名字会被自动结果覆盖，或反之 | 名册顶部固定一句：`你填的名字优先；重新整理不会覆盖`。 |

### 2.4 问题四：隐私沟通

**结论：不够，而且现在的"删除"与"已删除"文案存在实质不符。**

- 卡片写"音频只用来算向量，原始录音不保存"（client.js:1013）——这句话是对的（学前端只传 WAV base64、后端算完不留音频），但**没说向量存在哪、谁能读、删了会不会真没**；
- 标题写「默认不出本机」——"默认"暗示可被打开出网，而声纹计算确实全在本机（唯一出网是安装时从 GitHub/npm 拉文件，installer.js:19-20），口径应该更硬；
- `deletePerson` 是软删除：`store.js:127-137` 注释"样本留着可审计"，`p.status='deleted'`，**向量并未从磁盘移除**，但界面提示 `已删除 X（历史纪要不受影响）`（client.js:936）——用户会理解为生物特征已从磁盘消失；
- 同意记录是**后端补的**：`/voiceprint-enroll` 直接塞 `consent: { captureMethod, noticeVersion: 'v1', grantedAt: now }`（index.js:1825），`service.js:142-146` 还会再兜底造一个 `grantedAt`。界面上没有任何勾选或说明版本——这条"同意"是编造出来的，违反"无假记录"精神；
- 删除按钮是**单击即删**（client.js:1019），生物识别类数据不该没有二次确认。

| # | 问题 | 影响 | 具体改法 |
|---|---|---|---|
| P0-23 | 删除是软删除，文案说"已删除" | 用户基于错误认知放弃删除；合规口径站不住 | 文案改 `已从名册移除；向量仍留在本机库` + 提供 `彻底清除`（删人 + 删该人全部样本，`deletePerson` + `deleteSample` 组合，需要后端一个 `purge` 分支）；或改真删除并保留 `tombstones` 仅记 id/time。二选一，但**不能维持现状的措辞**。 |
| P0-24 | 同意是后端编的，界面无勾选 | 生物识别数据缺乏可追溯的用户同意；用户不知道自己同意了 v1 什么 | 卡片在录音按钮下加一次显式勾选：`我同意在本机保存这个人的声纹（只用于本机会后认人）`，勾选后才允许录音；前端把 `consent: { granted: true, noticeVersion: 'v1' }` 传上去，后端**只在 granted 为真时**写同意并记录 `grantedAt`。 |
| P1-25 | 删除入口不显眼、无确认 | 误删样本（还得重录 10 秒）；或找不到删 | `删除` 改两段式（点后按钮变 `确认删除`，3 秒内再点生效，或行内二次确认条）；同时补 `清空全部声纹`（需二次确认）与 `打开声纹库目录`（`runtime.dir` 已有，`/voiceprint` 可加 library dir）。 |
| P1-26 | 没写"模型跑在本机、不上传音频" | 用户担心声纹被传到云端 | 标题下固定一句：`模型在本机运行；声纹不外传`；安装时另写 `只有安装需要联网下载`。 |
| P1-43 | **未装模型时录音按钮不禁用**（client.js:1011 只按 `busy` 禁用；后端先读 PCM 再判模型：index.js:1812-1826 → service.js:105 先判 embedder） | 用户对着麦说满 12 秒、点结束才被告知"没注册成功"——正好是"点了没反应"的同类 | 未装模型时录音按钮 disabled，按钮位替换为 `一键安装` 主按钮 + 一行 `先装模型才能录声纹`；两者同一位置互斥，不并排。 |
| P1-44 | **录音生命周期无提示、无清理**：`getUserMedia` 权限弹窗期间界面不动（`setMsg('正在录音…')` 在 resolve 之后才设，client.js:841-863）；组件卸载（切 tab / 收面板）时没有 `useEffect` 清理，`MediaRecorder` 与音轨继续占用麦克风 | 权限弹窗期以为没点上；切走后麦克风仍亮却没人知道（隐私与"状态可感知"双重问题） | 点击后立刻 `setMsg('正在请求麦克风权限…')`；加卸载清理（停 recorder + 停 tracks + 清 timer），并在停止/失败时给一句可读结果。 |

### 2.5 问题五：状态可见性缺口（会后 identify 步骤）

**结论：能看到"跳过/完成 + 一行字符串"，看不到具体内容，且名册卡拿不到原因（原因只写在 `speakers.json` 里，没有接口读出来）。**

链路事实：

- `identify` 返回 `{ status: 'skip', reason }` 或 `{ status:'done', result: '2/3 位已认出' }`（index.js:5710-5714）；
- `postmeeting.js:109-110` 只把 `result` 字符串（或 skip 的 reason）写进 journal，`journal.js:311-318` 落到 `steps[identify] = { state, detail }`；
- `view-model.js:34-37` 再把 `detail` 原样给 `PipelineSteps`——所以步骤行**有** `认出说话人 · 已跳过 · 声纹模型未安装，说话人保持匿名`；
- 但每位说话人的 `reason`（`model-missing` / `not-enough-speech` / `mixed-voices` / 低分不认）和 `score` 只写进 `<会议目录>/speakers.json`（index.js:5701-5709，写失败仅 warn），而 `/speakers` GET 只读 `transcript-offline.jsonl` + `speaker-map`（index.js:1851-1863）——**没有任何界面能读这份结果**；
- `identify` 全程没有调用 `ctx.progress`（index.js:5669-5714），跑的过程中只有 headline 是"认出说话人"，没有"N/M 位"进展；
- 整理完成后 `headline/detail` 是通用句（view-model.js:32），不含认出数。

| # | 问题 | 影响 | 具体改法（都落在 view-model + 具体卡片行） |
|---|---|---|---|
| P0-28 | 认人结果没有出口 | 用户永远不知道"这场会认出了谁"，也无从判断值不值得维护声纹库 | `/speakers` GET 合并 `speakers.json`，每行返回 `{ label, sentences, seconds, sample, name, source, hasPrint, reason, reasonText, score }`；`view-model.js` 增加 `identity: { state, assigned, total, speakers: [...] }`（由 `runtime.speakers` 或新增 `runtime.identity` 注入 `/status`）。 |
| P1-29 | 状态卡完成态没有汇总 | 用户要翻到 tab 底部才知道认了几个人 | `view.detail` 在 `phase==='done'` 时拼一句：`整理完成 · 42 句 · 3 位 · 认出 2 位`（字段：`run.sentences`、`run.speakers`、`identity.assigned`）。渲染点：client.js:1193 的 `v.detail`（已有位置，不用加 UI）。 |
| P1-30 | 步骤行只有一行字符串，没有"为什么没认出" | 用户以为功能坏了或模型不行 | `PipelineSteps` 的 identify 行在 `detail` 后追加逐个原因：`说话人2 语音太少（需 ≥5 个窗口）`、`说话人3 与库里两人分数接近`（原因码→中文映射表放后端一处，前端不再写）。 |
| P1-31 | 认人过程中无反馈 | 会议长时这段十几秒到一分钟，看起来卡住 | identify 里按 label 循环时调用 `ctx.progress('已认出 1/3 位')`（`PipelineSteps` 已支持 `progress`，client.js:1099）；`progress.js` 现有的 1 秒节流会阻止刷屏。 |
| P2-32 | 名册与认人结果不联动 | 名册显示姓名，但不知是自动还是人工（同 P1-20） | 名册行右侧 tag：`自动认出` / `我填的` / `未认出（原因）`。 |
| P3-33 | `speakers.json` 写失败只 warn（index.js:5707-5709） | 结果可能悄悄丢 | 该失败要进 `journal`（`pipeline.progress` 或 `issues`），卡上有一行 `识别结果未落盘：<原因>`。 |

**建议的字段（供实现，非代码补丁）：**

```
view.voiceprint = { enabled, ready, reason, modelBytes, runtimeBytes, modelId, dim }
view.identity   = { state, assigned, total, speakers: [{ label, name, source, hasPrint, reason, reasonText, score }] }
steps[i].action = { label, tab, focus }   // 可选，仅 identify 用
/voiceprint    += enabled, model.dir, library.dir, runtime.bytes, install.phaseLabel
/speakers      += 每行 source / hasPrint / reasonText / score（合并 speakers.json）
```

### 2.6 问题六：一致性（视觉语言 / 间距 / 按钮层级）

**结论：三张卡与面板其它部分不像同一套设计系统，而且"同一个东西两种写法"的地方有好几处。**

现成的设计系统其实存在但没被用起来：

- `Card` 组件（client.js:737-743：`bg2` 背景 + `radius 10` + header 分隔线 + `extra` 槽位）在**整个文件里没有任何 `h(Card` 调用**；
- `S.card`（client.js:85：`radius 10` + `bg2` + `margin 8 0`）只被 `DepsCard` 用；
- 三张新卡各自手写 `section`：`radius 8`、**无背景**、`padding '10px 12px'`（client.js:792、985、1065）——所以它们在页面上比 `S.card` 更"平"，更容易被看成裸文本。

## 4. 明确"不建议做的"

- **不要给校验/解压阶段编百分比**（哪怕是"按文件数估算"）。这两个阶段没有可测进度，正确做法是不确定态条 + 时间预期文案；用户已明确禁止假进度。
- **不要新增独立的"声纹设置页"或第 5 个 tab**：入口分散比入口靠后更糟；用状态卡 inline 提示 + 分组标题引流就够。
- **不要把模型/运行库的安装并进「安装与依赖」的 `DepsCard`**：那是 npm 插件安装（`dsh plugin add`），混用会造出第二套状态源，直接违背"所有显示底层共用一套配置"。
- **不要给声纹加"暂停/断点续传"**：首版收益低（失败可重试），实现成本高（分片、续传状态、cleanup），先把"看得见进度 + 能取消 + 能重试"做扎实。
- **不要在界面上暴露相似度分数、窗口数给普通用户**：只放「详细信息」折叠里，主界面说人话（P1-30 的中文原因即可）。
- **不要给名册加"试听这段录音"**：会立刻引出"你们保存了音频"的错觉，与 V-26 冲突；要听就明确说是"打开会议文件夹里的整段录音"。
- **不要做同名自动合并 / 模糊匹配**：`speaker-map.js:15` 已定规矩"只认明确映射"，模糊匹配会制造编造姓名，属产品红线。
- **不要用 toast/一次性提示承载安装进度**：面板可能被收起或用户切 tab，进度必须落成卡片内的持久状态。
- **不要在名册里同时保留"每行保存"和"保存全部"两套动作**：二选一（推荐只留「保存全部」+ 每行"未保存"标记）。
- **不要为"录音失败重试"保留上一次录音**：10-12 秒重录成本低于解释"我们其实临时留了你的录音"的信任成本。

## 5. 验收清单（人工 3 分钟可逐条验证）

> 前置：改完需重启 DSH（Host 改动）+ 刷新面板；准备一台"从未装过声纹模型"的机器或先删掉 `数据目录/voiceprint/models`。
> 每条都是"睁眼可判"的外部观察，不依赖日志。

**入口（1 分钟）**
1. 打开面板，停在默认「实时转写」tab：状态卡下方能直接看到一行 `声纹未就绪：会后不会自动认人` + 「去安装」按钮 → 点它一次落到声纹卡（≤2 次点击、10 秒内）。
2. 点面板顶部「诊断」按钮 → 若声纹仍不可用，说明 inline 提示不应只出现在某个 tab。

**安装（2 分钟，可含一次断网重试）**
3. 声纹卡首屏：只有一个主按钮 `一键安装（模型 25 MB + 运行库 110 MB）`，按钮上方能看到 `装好后…` 与 `不装也能用…` 两句；同一时刻「录一段注册」是灰的并写着 `先装模型才能录声纹`。
4. 点安装后 **3 秒内**：出现阶段文字 + 真实字节数（`已 x / y MB`）且数字在动；出现「取消」按钮；按钮变成 `正在安装…`。
5. 观察 60 秒：进度只单调上升，**不会从 100% 掉回 0%**；模型阶段与运行库阶段各有明确"第 1/2、2/2 步"标记。
6. 安装中点「取消」：立刻出现 `正在取消…`（按钮不可再点），随后出现 `已取消，可重新安装`，且**之后不会自己变成"完成"**。
7. 断网再点安装：出现 `安装未完成` + 具体原因 + 「重试安装」「打开模型目录」两个动作；点「打开模型目录」能真的打开资源管理器到那一步。
8. 装完：状态行变 `模型已就绪 · 可以录声纹了`，主按钮变成「录一段注册（≥10 秒）」。

**录音与隐私**
9. 点录音（未勾同意）：提示要求先勾选，不启动麦克风；勾选后点录音立刻出现 `正在请求麦克风权限…`，允许后立刻变成 `正在录音：已 N 秒`，秒数在跳。
10. 录音中切到「实时转写」再切回：要么录音仍在并显示，要么已明确停止；系统麦克风指示灯**不能持续亮着而界面无任何提示**。
11. 点删除出现 `确认删除` 二次确认；删除后的提示包含"向量仍在本机库"，且能找到「彻底清除」或「打开声纹库目录」。

**两套人名**
12. 声纹卡标题是「我认识的人 · 本机声纹」、名册是「这场会谁是谁」，两者的输入框提示词**不互相串**（在声纹框输入时不会出现名册专属的提示串）。
13. 名册填 3 个名字 → 点一次「保存全部」→ 3 行都显示已保存；**再等 30 秒（期间有后台事件）输入内容不被清空**。
14. 名册中一个名字在声纹库存在 → 显示 `已有声纹`；不存在的 → `无本机声纹`。

**认人结果**
15. 会后整理跑到 identify：步骤行能看到 `认出说话人 · 进行中` 且带 `已认出 1/3 位` 这类进展（不是空转）。
16. 整理完成：状态卡 detail 里能看到 `42 句 · 3 位 · 认出 2 位`；步骤行跳过时写清原因（`声纹模型未安装` / `配置里未启用本机声纹`）；名册对应行显示 `自动认出` 或 `我填的`。
17. 名册填名字后点「用录音重新整理」：纪要正文出现该姓名（人工填的名字被采用，没有被自动结果覆盖）。

**一致性与空态**
18. 打开「纪要与产物」逐块看：三张卡的外壳、左右内边距、卡间距（12px）一致；同页只有**一个**主按钮；按钮高度只有 28 与 24 两种。
19. 在没有任何会议的干净环境打开该 tab：声纹卡照常可用（能装能录），名册卡显示 `这场会还没有转写结果…`，**不整块消失**。
20. 断网/关掉插件接口后打开该 tab：卡片显示失败原因 + 「重试」，不会永远停在 `正在读取…`。
