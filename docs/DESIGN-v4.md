# SoulMirror 4.0 设计方案（云端实时流式 ASR · 无说话人 · 可离线验证）

> **取代 3.0**。3.0 的"本地 SenseVoice + 自造分段器"作废：
> 你选择云端实时流式 ASR，批处理伪装流式那一整套复杂度（分段器、重叠去重、队列背压、228MB 模型下载）全部不需要了。
>
> 保留 3.0 中仍然成立的部分：取消说话人识别、Source 抽象、无会议软件验证体系、生产级工程要求。

---

## 0. 决策与后果

| 决定 | 后果 |
|---|---|
| ASR = 云端实时流式（DashScope `paraformer-realtime-v2`） | 延迟回到 **1–3 s**，有 partial（真正的"逐字出字"） |
| 取消说话人识别 | 无 diarization；Agent 判定只看文本 |
| 需要网络 + key | 必须有降级路径，不能静默失败 |
| 按小时计费 | 需要成本预算与熔断 |

### 与 3.0 的对比（为什么这样更省事）

| 项 | 3.0 本地 SenseVoice | 4.0 云端流式 |
|---|---|---|
| 延迟 | 段长 + 推理 ≈ 4 s | **1–3 s** |
| partial（逐字） | 无 | **有** |
| 分段器/去重 | 必须自己造 | **不需要** |
| 首装下载 | 228 MB | **0** |
| 成本 | 0 元 | 小时级几毛~1 元 |
| 离线 | 可以 | **不行**（降级处理） |
| 隐私 | 音频不出机 | 音频出云 |

## 1. 已验证的关键事实（都在这台机器上跑过）

这些不是推测，是实测结论，方案必须绕开它们的坑：

| 事实 | 验证方式 | 设计含义 |
|---|---|---|
| WS 握手可用（`task-started`） | 独立进程探活 | 连通性没问题 |
| 喂 5.1s WAV 能出完整整句 | 脚本回放 | 客户端解析正确 |
| **只有停顿 800ms 才落句** | 连续会议实测落后 2–24 s | 必须**强制落句**（4 s 未变且 ≥8 字） |
| 不支持说话人分离 | 参数不存在 | 已取消该功能 |
| 采集设备环回可能静音（HDMI） | 环回 RMS 0.0000 vs MIPI 0.0454 | 设备**启动时锁定**，不自动切换 |
| 换设备 = 杀进程 = 丢音频 | 实测抖动 | 只在启动时选一次 |
| 采集进程本身稳定 | 30 s 零空档 963 KB | 退出是切换逻辑导致的，不是采集问题 |

## 2. 总体架构

```
┌──────────────────────── DSH Host ────────────────────────┐
│                                                           │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐  │
│  │ meeting-core │──▶│ audio-engine │──▶│ asr-stream   │  │
│  │ 状态机/编排   │   │ 采集/设备锁定 │   │ WS 实时识别   │  │
│  └──────┬───────┘   └──────────────┘   └──────┬───────┘  │
│         │                                     │           │
│         │        ┌──────────────┐             │           │
│         ├───────▶│ agent-brain  │◀────────────┘           │
│         │        │ 判定/任务/发言│                         │
│         │        └──────┬───────┘                         │
│         │               ▼                                 │
│         │        ┌──────────────┐   ┌──────────────┐      │
│         ├───────▶│ dsh-bridge   │   │ archive      │      │
│         │        │ session/schedule│  │ 纪要/知识库   │      │
│         │        └──────────────┘   └──────────────┘      │
│         └───────▶ obs（健康/指标/事件）                     │
└───────────────────────────┬───────────────────────────────┘
                            │ HTTP + SSE
┌───────────────────────────┴───────────────────────────────┐
│                    DSH Client（原生 slot）                  │
│  sidebar.panellist → main#meeting   小窗/会话字幕/设置页    │
└───────────────────────────────────────────────────────────┘
```

**分层原则**：外部世界全部走接口，每个接口有真实实现与模拟实现（这是"可离线验证"的全部秘密）。

```ts
interface SignalSource   { poll(): Promise<MeetingSignal> }
interface AudioSource    { chunks(): AsyncIterable<Uint8Array> }   // 16k mono PCM16
interface Transcriber    { start(): Promise<void>; feed(pcm): void;
                           onEvent(e: Partial|Sentence|Error): void; stop(): Promise<void> }
```

## 3. 转写子系统

### 3.1 链路

```
capture-stream（mbridge，16k mono PCM16）
   → asr-stream（DashScope WS，长连接）
       ├─ partial（~200ms 刷新） → 实时字幕（不落库）
       ├─ sentenceEnd           → 正式行（落库 + 事件）
       └─ 4s 无变化且 ≥8 字      → 强制落行（去重）
```

**为什么两个落库口**：实测会议里几乎没有 800 ms 停顿，只靠 `sentenceEnd` 会让转写落后几十秒。强制落句是必须的。

### 3.2 断线重连（生产必备）

```
WS 断开
  → 指数退避重连：1s / 2s / 4s / 8s（上限 15s，最多 6 次）
  → 保留最近 3 s PCM 作为衔接缓冲（重连后补发，避免断点丢词）
  → 若重连期间丢了音频，在 transcript 里写 gap 标记：
       { t, text: '（此处中断 N 秒）', gap: true }
  → 6 次仍失败：标记 error，停止采集，UI 给出可操作提示
```

**不允许**：静默丢音频、静默断连、UI 显示"正在转写"但实际没在听。

### 3.3 降级链（有 key 才能用，但坏了不能死）

| 状态 | 行为 |
|---|---|
| 正常 | 云端流式 |
| 无 key / key 失效 | 状态明确显示"未配置语音识别"，引导去设置页；**不启动采集**（避免白花钱和假运行） |
| 网络中断 | 重连（见上）；同时 UI 显示"识别中断中" |
| 连续失败 | 降级到**本地 DSH SenseVoice**（若已就绪）→ 否则停止并提示 |
| 成本超预算 | 提示 + 可配置自动停止 |

本地 SenseVoice 作为**可选备用 provider**保留接口（`Transcriber` 抽象），但**不做默认**、不预下载模型。

### 3.4 延迟与预算

| 指标 | 目标 |
|---|---|
| partial 刷新 | ≤ 500 ms |
| 落库延迟 P50 / P95 | ≤ 2 s / ≤ 5 s |
| 发送背压 | 未就绪时丢帧计数；累计丢 > 2 s → 重连 |
| 成本 | 每小时会议约 0.5–1 元；`asr.hourlyBudget` 超限告警 |

## 4. 音频采集

```
设备选择（启动时一次，锁定）：
  1. 配置 devices.capture 显式指定
  2. 否则 = 系统默认播放设备（mbridge default）
  3. 例外：若别的设备正在出声而默认≈0 → 用它（只判断这一次）
```

- **永不自动切换**（换设备必须重启进程，必然丢音频）
- 长时间无转写：**只报警不切换**，并指出"有声音的是 X"
- 进程监督：退出后指数退避重启（≤5 次），超限停止并上报
- 健康：`bytes / silentMs / lastChunkAt / restarts`

## 5. 会议检测与会议号

**检测**：进程白名单 → 窗口类名/标题 → 评分（腾讯会议 100 / 移动会议 90 / 飞书 80 / 钉钉 70 / Zoom 60 / Teams 55），<60 视为未开会。

**"在会中"三信号任一**：会中窗口类名 / 标题≠软件名 / 该进程占用麦克风（`state=1`，移动会议靠这条）。

**会议号**（命中即停，都不中就显示未识别，允许手填）：

```
会议内文本控件 → 带标签文本（"移动会议：379422987"）→ 邀请链接（…/share/xxx）→ 裸号（排除 19xx/20xx）
```

## 6. 入会与创建

```
链接优先 → 官方 API（有凭据）→ UIA 填号（标定）→ 自愈标定（每月限 1 次）
```

- 标定坐标存相对比例，不写死像素
- 到点自动参会复用 DSH `schedule`（自动化任务），不自造定时器
- 已在会中 → 绝不重复入会

## 7. Agent 自动化（无说话人依赖）

总开关 `enabled` + 模式 `mode: transcribe | agent`。

**判定只看文本**：

| 信号 | 权重 |
|---|---|
| 称呼（名字/昵称/职位，可配） | 0.40 |
| 请求句式（帮我/能不能/你看下） | 0.30 |
| 第二人称（你/您/你们） | 0.10 |
| 上下文 LLM 判定（可选） | 0.20 |

阈值 0.6；同话题冷却 60 s；每分钟判定 ≤1 次；每小时发言 ≤N 次。

**必须写在 UI 的限制**：没有说话人识别，多人会议里"谁在说"不可知，误触发概率随人数上升。

**执行**：组上下文 → 需操作则建/复用 DSH 会话 → TTS 播到虚拟声卡 → 同时插一条 `role=assistant` 到转写流（UI 可见"我说了什么"）。

发言安全：用户占麦 → 延后 2 s 重试 ≤3 次；>30 s 截断；未配 `devices.speak` → 只本地播放。

## 10. 无需会议软件的验证体系

### 10.1 四层

| 层 | 内容 | 依赖 |
|---|---|---|
| L1 单元 | 会议号解析、判定打分、状态机、重连退避、去重 | 无 |
| L2 转写 | **wav 按实时节奏喂真 WS 客户端 → 断言文本** | 需 key + 网络 |
| L3 端到端 | 假 SignalSource + 假 AudioSource + 假 Transcriber → 检测→转写→判定→归档 | **无桌面、无网络** |
| L4 演练模式 | 内置样例音频 + 假会议身份，30 秒看全流程 | 无 |

L2 已被验证可行（我用 5.1 s WAV 回放拿到了完整整句）。

### 10.2 演练模式（产品功能）

```
meeting_demo start
→ ScriptedSignal（"演练 · 983 593 253"）
→ 内置 fixtures/demo_meeting.wav
→ UI 横幅「演练中 · 不连接真实会议 · 不会发言」
→ 结束出纪要，但不写知识库、不发汇报
```

### 10.3 混沌注入

`SOULMIRROR_FAULT`：

```
kill-capture   采集中途死掉 → 自动恢复且不抖
drop-ws        WS 断开 → 退避重连 + gap 标记
slow-ws        推理变慢 → 背压丢帧计数
disk-full      写盘失败 → 报错可行动
bad-key        key 失效 → 明确提示，不假运行
no-network     断网 → 重连 + 提示
```

### 10.4 测试资产

```
tests/fixtures/
├── demo_meeting.wav / .expected.json   # 90 秒多轮对话（TTS 合成，可复现）
├── silence_30s.wav
└── cut_boundary.wav
```

约定：`SOULMIRROR_TEST=1` 时禁止真实桌面/网络/麦克风；凡需真实 key 的用例自动 skip 并明确标注。

## 11. 生产级工程要求

不能承诺零 bug，承诺**不静默失败、可恢复、可诊断**：

| 机制 | 做法 |
|---|---|
| 状态机 | 单一所有者，显式 states/events/guards，非法迁移抛错 |
| 不变量 | 运行期断言（capturing ⇒ 恰一个采集进程；capturing ⇒ ASR 已连接） |
| 幂等 | start/stop/join/archive 可重复调用 |
| 超时 | 每个外部调用都有超时 |
| 熔断 | LLM 连败 3 次 → 降级只转写并告知 |
| 预算 | CPU/内存/磁盘/Token/ASR 小时数，超限降级 |
| 可观测 | `/health`（延迟 P50/P95、重连次数、丢帧、队列）+ `events.jsonl` |
| 诊断包 | 一键导出 24 h 事件 + 脱敏配置 |
| 金丝雀 | 新版先跑演练模式，再允许接真实会议 |

**SLO 基线**

| 指标 | 目标 |
|---|---|
| 端到端延迟 P50 / P95 | ≤ 2 s / ≤ 5 s |
| 60 分钟会议采集重启 | 0 |
| WS 重连后断点丢失 | ≤ 1 处，且必须有 gap 标记 |
| 崩溃率 | 0 |
| CPU 均值 | ≤ 8% |
| 内存峰值 | ≤ 300 MB |

## 14. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| 网络依赖 | 断网即失效 | 重连 + gap 标记 + 本地 SenseVoice 作为可选备用 |
| 成本累积 | 长时间开会花钱 | 小时预算 + 告警 + 可自动停 |
| 音频出云 | 合规 | 明确告知 + 可关 + 本地备用路径 |
| 供应商锁定 | 换要改代码 | `Transcriber` 抽象，DashScope 只是默认实现 |
| 只靠句末落句 | 落后几十秒 | 4 s 强制落句（已实测必要） |
| HDMI 环回静音 | 采集不到 | 设备锁定 + 明确报错 |
| 无说话人 | Agent 误触发 | 阈值 + 冷却 + 预算 + UI 警示 |
