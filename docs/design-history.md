## v4 · 分层与"活在 DSH 里"

**核心变化**：插件不再自己造一套会话/调度，而是**寄生在 DSH 的既有能力上**。

- 会话：`dsh-session.js` 通过 `sessionController` 创建/驱动，不再自建状态机
- 定时：复用 DSH 的 `schedule` 服务（界面里就是「自动化任务」，可见可删可持久化）
- 模型：优先用 DSH 的 `llm` 服务，不再强绑某一家 API
- 知识库：通过 `dsh-knowledge` 的本地管理 API 写入，不重复实现存储

**带来的取舍**：

| 好处 | 代价 |
|---|---|
| 不重复造轮子，行为与 DSH 一致 | 依赖宿主版本，接口变了要跟 |
| 任务在界面可见、可删 | 限定了"必须是 DSH 插件" |

## v3 · 数据与判断分离

**核心变化**：把"外部世界"与"业务判断"切开，让后者可测。

- `sources.js`：桌面音频 / 脚本信号统一成同一接口 → 能用脚本复现会议
- 判定逻辑抽成纯函数：`trigger-rules`、`advice-trigger`、`dedupe`、`segment-merge`
- 引入演练模式（`demo.js`），不依赖真实会议也能跑全链路

**为什么重要**：会议场景难以复现（要真的有人开会）。
不抽离就永远只能"手动试试看"，出错无法回归。

---

## v2 · 从"能听"到"能记"

**核心变化**：实时转写之外，补上会后整理。

- 实时 ASR（低延迟，但会断句、会丢）
- 会后重转写（准确，可带说话人）
- 纪要 → 落盘 → 写知识库

**踩过的坑**（都已成为测试）：

- 实时断句产生的碎片要合并，否则一句变三句
- 中间结果与最终结果会重复到达，需要按相似度去重
- 会后整理必须**幂等**：重复触发不能写第二份纪要

---

## 贯穿三版的一条线

每一版都在减少"假装成功"：

```
v2：会后整理失败了，就明确报失败
v3：判断逻辑可测了，出错能定位
v4：不再自建调度，行为与宿主一致
之后：写库失败报失败、模型断开报断开、内存临近上限先停
```

这条线现在写在 [philosophy.md](philosophy.md) 的「不假装」一条里。
