# 音频设备

采集设备怎么选、为什么选定后不再变。

## 🎧 采集设备怎么选（选定后不再变）

只判断一次，之后全程不变——换设备要重启采集进程，中间必然丢音频。

优先级：

1. 配置里显式写了 `devices.capture` → 用它
2. 此刻**正在出声**的设备（说明应用实际往这里播）
3. 系统默认播放设备（`mbridge default` 报的那个）

选定后会写进状态，方便核对：

```
/api/soulmirror/status → session.captureDevice = "扬声器 (MIPI ...)"
日志：[soulmirror] 采集设备锁定：扬声器 (MIPI ...) — 系统默认播放设备
```

长时间没有转写时**只报警不切换**：会告诉你"当前设备环回是静音，有声音的是 XXX，请把系统播放设备切到它"。

> 背景：这台机器的 H27P6 (HDMI) 环回采集恒为静音（音量表有电平，WASAPI 环回返回全零），
> 采它等于什么都听不到。所以"自动挑最响的设备"反而会踩坑，改成按默认设备优先。

## 🎤 双路采集：环回 + 麦克风（补上你自己的发言）

**根因**：会议客户端**不会**把自己的麦克风声音再输出到扬声器（否则参会的人会听到自己的回声），
所以环回里只有"别人的声音"。只采环回时，**用户自己说的话根本不在转写里**——这就是
"只采集声卡，我说话的声音没有啊"。

做法：环回之外**同时采一路麦克风**（`capture-stream --mode device`，走 `FindDevice(1,…)`），
两路都是 16k/单声道/16bit，按字节偏移对齐后逐样本相加，混成一路再送识别。

| 键 | 默认 | 含义 |
|---|---|---|
| `devices.mixMic` | `true` | 同时录我的麦克风（默认打开，否则漏掉用户自己的发言） |
| `devices.micDevice` | 空 | 麦克风设备名/id（空 = 系统默认采集设备）；界面「设置 → 采集」可填 |

**混音规则**（`lib/audio-mix.js`，纯函数、可单测）：

- 加法用 int16 **饱和裁剪**：两路同时有人说话会超过满量程，不裁剪就是数值回绕（刺耳爆音）。
- 长度取**较长的一路 + 较短的一路补零**：两路是各自独立启动的进程，尾巴长短不齐，截短会切掉后说话那一路的尾部。
- 流式 `PcmMixer` 只在**两路都够一块（100ms）**时才混，用完两边偏移同时前进——不会把 A 的第 2 秒混到 B 的第 1 秒。
- 一路落后 ≤1 秒：等它；落后 >1 秒：清掉它的积压（计入 `dropped`）并按静音补位继续出流；
  单路缓冲超过 5 秒：丢最旧的并计数。所有丢弃/中断都在 `/status` 的 `session.mixStats` 与 `mixWarn`、界面「采集通道」里可见。

**失败不整体失败**：任一路退出只写清原因（`lastError`：如"麦克风路中断，当前只有环回（转写里可能没有你自己的发言）"），
另一路继续转写；麦克风那一路按退避自动重起，恢复后自动加回（重启时清空缓冲重新对齐，宁可 ≤1 块缝隙也不混错位音频）。
`captureMode === 'device'` 时不叠加麦克风——那时采的本来就是麦克风，再叠一路只会把同一句话录两遍。
